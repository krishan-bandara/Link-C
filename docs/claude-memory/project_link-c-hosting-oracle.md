Link-C now runs on an Oracle Cloud (Pay As You Go account, Always Free resources only, Mumbai) server: VM.Standard.A1.Flex ARM, 1 OCPU / 6 GB (free allowance is 2 OCPU / 12 GB total, resize via Edit shape was not found in console, owner will handle later), Ubuntu 24.04 Minimal aarch64, hostname linkc-vcn, user `ubuntu`, ephemeral public IP 140.245.3.119 (may change). Reason for the move: the old home VM measured only 5.4 Mbit/s up, 11.6 down, 351 ms ping, which made uploads and media viewing very slow.

**Why:** owner wants fast uploads/media at $0-2/month. The $1 monthly Oracle budget alert was requested (verify it exists).

**How to apply:**
- SSH key lives at `D:\My_Docs\oracle_cloud\ssh-key\ssh-key-2026-10-21.key` (copy in WSL at ~/.ssh/linkc.key). Never read or commit it.
- Repo on server: `~/_work/Link-C` (cloned via read-only GitHub deploy key). On the Oracle server the env file is a plain `.env` inside the project folder `~/_work/Link-C/.env` (gitignored; NOT the old VM's `_allenvs/.env_linkc`, which only applies to the old home VM). Never read or print env files (the auto-mode classifier blocks it anyway).
- Deploy: `git pull`, then `sudo docker compose up -d --build --force-recreate` (docker group not applied yet, so sudo).
- `data/` MUST be `chown -R 1000:1000` or every upload/media view fails with EACCES (hit this twice). Already noted in docs/DEPLOY.md.
- This server has 1 CPU: docker-compose.yml cpu limits now come from `APP_CPUS` / `WORKER_CPUS` env vars (defaults 1.5 / 1.0). Server needs APP_CPUS=1, WORKER_CPUS=0.5 appended to `~/_work/Link-C/.env`, and a `git checkout docker-compose.yml` before pull if it was edited with sed. The compose change in the D: repo was NOT yet committed when written.
- Cloudflare: a NEW tunnel `linkc-oracle` for this server (old tunnel Tunnel-Linux-prod-VM, with n8n/ssh, must keep its token). Hostname link-c.innoforge.dpdns.org must point to the new tunnel -> http://localhost:3005. Old home VM containers to be stopped only after the new one is verified.
