1. Network architecture

2. Key network rules

No inbound ports

The VM dials out to Cloudflare. Nothing is forwarded on your router, and your home IP is never published.

Everything over TLS

Browser to Cloudflare uses HTTPS, and the tunnel is encrypted. Inside the VM, services talk on a private Docker network.

n8n kept apart

Separate Docker network, volumes and secrets, and no shared database, so a problem in one cannot reach the other.

3. High-level processes

Login

Invite and magic link

  1. Owner invites an email (and phone) in the admin panel.
  2. Member opens the invite and requests a login link.
  3. Link is single-use and expires in 10 minutes, with a confirm page and 6-digit code backup.
  4. First login shows the privacy notice and SMS notice to accept.
Chat

Send a message

  1. Browser sends over WSS through Cloudflare and the tunnel.
  2. App validates and saves it in Postgres under Row Level Security.
  3. Supabase Realtime pushes it to the recipient.
  4. Delivered, read and typing states update live.
Normal media

Photo or video kept

  1. Browser uploads in 8 MB chunks (each under Cloudflare's 100 MB cap); photo max 10 MB, video max 300 MB.
  2. Server assembles, checks real file type, strips EXIF.
  3. Encrypts with a per-file key (AES-256-GCM).
  4. Stores the encrypted file in the private B2 bucket.
  5. Viewing streams it back, decrypted, through your own domain.
Snap

One-time or timed media

  1. Encrypted temp file on the VM only; never in B2 or backups.
  2. Recipient opens once; server marks it viewed and issues a 30-second link.
  3. Viewer auto-closes after 1-10 seconds, or when closed (no limit).
  4. File is deleted right after viewing; unopened snaps are deleted after 24 hours.
SMS

Offline alert

  1. Message arrives while the member has been offline for 2 minutes.
  2. Worker sends one system-style SMS using the owner's template.
  3. No more SMS until the member opens the app and goes offline again.
  4. Daily and monthly caps apply; everything is set in the admin panel.
Location and calls

Consent-based

  1. Owner taps Request location; the member accepts 15 min, 1 h or 8 h, or declines.
  2. A banner shows while sharing; data is deleted after the window.
  3. Calls: app issues a LiveKit token; audio and video go device to LiveKit.

5. Security layers

LayerControls
EdgeCloudflare WAF and rate limits, Access login on /admin, HTTPS and security headers
IdentityInvite-only, single-use magic links, role stored in the database, owner checks on the server
DataRow Level Security on every table, validated input, escaped message text, audit log without content
MediaReal file-type checks, EXIF removal, per-file encryption, bucket-scoped B2 key, 30-second links, no public URLs
HostSSH keys only, firewall deny inbound, auto updates, fail2ban, pinned Docker images, n8n isolated
Secrets and keysDocker secrets, never in git; master encryption key copy kept offline in a password manager
RecoveryNightly encrypted DB backup to B2 (snaps excluded), one tested restore

Honest limits: a recipient can still screenshot or film a snap, and screenshot detection is best effort. Your disk is not fully encrypted, so someone with physical access to the VM could reach the database and keys. Losing the master key makes stored media unreadable.
